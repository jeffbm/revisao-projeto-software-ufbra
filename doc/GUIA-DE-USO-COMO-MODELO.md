# Guia para utilizar este projeto como modelo futuro

## O que deve ser mantido

Em um novo projeto, mantenha a lógica documental:

1. contexto;
2. problema;
3. objetivo;
4. partes interessadas;
5. escopo;
6. requisitos;
7. regras;
8. casos de uso;
9. UML;
10. arquitetura;
11. dados;
12. rastreabilidade;
13. testes;
14. critérios para iniciar implementação.

## O que deve ser substituído

Não copie mecanicamente:
- nomes das classes;
- requisitos;
- regras de negócio;
- casos de uso;
- dados;
- testes.

Esses itens devem nascer do novo problema.

## Sequência recomendada para trabalho acadêmico

```text
README
→ visão e escopo
→ requisitos
→ casos de uso
→ UML
→ dados
→ modelo de processo escolhido
→ rastreabilidade
→ plano de testes
→ implementação
→ testes executados
→ manutenção e versão final
```

## Regra de qualidade

Se um requisito não pode ser ligado a uma decisão de projeto e a uma forma de teste, provavelmente ainda está pouco claro.
